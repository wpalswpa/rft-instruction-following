# 작은 지시 모델의 형식 지시 위반을 자기 응답 거부 샘플링 LoRA로 줄일 수 있는가

Qwen2.5-0.5B-Instruct가 "정확히 3개의 글머리표로", "쉼표를 쓰지 마라" 같은 형식 지시를 얼마나 어기는지 재고, 검사기를 통과한 자기 응답만으로 LoRA 미세조정(거부 샘플링 미세조정, RFT)을 해서 위반이 줄어드는지 확인한 실험이다. 같은 효과를 시스템 프롬프트 한 줄로 얻을 수 있는지도 함께 비교했다. GPU 없이 노트북 CPU(i7-8750H, 메모리 16GB)에서 돌렸다.

평가 기준·비교 조건·성공 기준은 학습 전에 [설계서](docs/blueprint.md)로 커밋했다(커밋 3bba7e1). 실행 중 바꾼 것은 설계서 9절 변경 기록에 있다.

## 결과

시험 160문항(처음 보는 주제 20개, 처음 보는 제약 값)에서 모든 제약을 지킨 문항의 비율이다.

| 조건 | 문항 단위 통과 | 제약 단위 통과 | 응답 단어 수 중앙값 | 산술 대조(60) | 요청 안 한 형식(40) |
|---|---:|---:|---:|---:|---:|
| B0 기본 모델 | 23/160 (14.4%) | 22.1% | 93 | 47 | 0 |
| B1 기본 + 엄격 시스템 문구 | 23/160 (14.4%) | 21.6% | 84 | 46 | 0 |
| M1 RFT LoRA | **64/160 (40.0%)** | 50.9% | 64 | 46 | 0 |

- **프롬프트 한 줄로는 오르지 않았다.** B1은 B0와 같은 23문항이다.
- **M1은 B1보다 25.6%p 높다.** M1만 통과한 문항 45개, B1만 통과한 문항 4개, McNemar 정확 검정 p = 8.2×10⁻¹⁰, 차이의 95% 부트스트랩 구간 18.1~33.1%p.
- **학습 전에 커밋한 성공 기준 셋을 모두 만족했다.** (1) B1 대비 +10%p 이상이고 p < 0.05, (2) 산술 정확도 하락 5%p 이하(47 → 46, −1.7%p), (3) 제약 없는 문항에서 요청하지 않은 형식 0/40.

| 제약 | B0 | B1 | M1 | 학습 예시에 들어간 문항 |
|---|---:|---:|---:|---:|
| json_keys | 0/12 | 0/12 | 12/12 | 20 |
| bullets | 5/25 | 4/25 | 20/25 | 32 |
| quote_wrap | 16/30 | 15/30 | 27/30 | 19 |
| lowercase | 14/38 | 14/38 | 26/38 | 19 |
| max_words | 3/31 | 2/31 | 11/31 | 5 |
| end_phrase | 8/25 | 11/25 | 10/25 | 7 |
| no_commas | 1/35 | 1/35 | 6/35 | 4 |
| keyword_twice | 2/26 | 1/26 | 1/26 | 21 |

시험의 JSON 키(`name`, `reason`)와 글머리표 개수(2·6개)는 학습에 없던 값인데도 올랐다. 기본 모델은 JSON을 코드 블록(```)으로 감싸 0/12였다. 반대로 학습 예시가 적었던 끝 문구·쉼표 금지는 거의 그대로였고, "단어를 두 번 이상" 지시는 학습 예시가 21개였는데도 오르지 않았다.


## 어떻게 했나

```
학습 문항 360개 (주제 60개 × 제약 1~2개, 시드 1234)
  → 기본 모델 응답 4개씩, 온도 0.8 (표본 1,440개)
  → 검사기로 모든 제약을 통과한 응답만 남김 (202개)
  → 문항당 가장 짧은 통과 응답 하나 (학습 예시 115개)
  → LoRA 미세조정 (r 16, q·k·v·o, 응답 토큰에만 손실, 2에폭, 최적화 29단계)
  → 시험 160문항 (처음 보는 주제 20개 + 처음 보는 제약 값)에서 세 조건 비교
```

| 조건 | 모델 | 시스템 문구 |
|---|---|---|
| B0 | 기본 모델 | Qwen 기본 문구 |
| B1 | 기본 모델 | 기본 문구 + "Follow every formatting instruction in the user's message exactly." |
| M1 | LoRA 미세조정 모델 | Qwen 기본 문구 |

평가는 탐욕 디코딩(최대 256토큰)이고, 모델 기본 생성 설정의 반복 벌점 1.1이 모든 조건에 똑같이 들어간다. 판정은 [src/constraints.py](src/constraints.py)의 결정적 함수가 하고, 함수마다 통과·실패 예시를 [tests/](tests/test_constraints.py)에 두었다.

## 학습 데이터가 치우친 방식

기본 모델의 표본 통과율이 제약마다 크게 달라서, 학습 예시도 쉬운 제약 쪽에 몰렸다.

| 제약 | 표본 단위 통과 | 학습 예시에 들어간 문항 |
|---|---:|---:|
| quote_wrap (큰따옴표로 감싸기) | 87/232 (0.38) | 19/58 |
| bullets (정확히 n개 글머리표) | 71/240 (0.30) | 32/60 |
| lowercase (전부 소문자) | 68/240 (0.28) | 19/60 |
| keyword_twice (단어 두 번 이상) | 82/348 (0.24) | 21/87 |
| json_keys (키를 정한 JSON) | 28/156 (0.18) | 20/39 |
| end_phrase (정한 문구로 끝내기) | 38/252 (0.15) | 7/63 |
| max_words (n단어 이하) | 26/276 (0.09) | 5/69 |
| no_commas (쉼표 금지) | 9/272 (0.03) | 4/68 |

제약 두 개가 붙은 문항은 학습 예시 115개 중 12개뿐이다. 단어 수 상한과 쉼표 금지는 학습 신호가 거의 없다.

## 이 결과로 말할 수 없는 것

- **응답이 짧아졌다.** 단어 수 중앙값이 93에서 64로 줄었다. 거부 샘플링에서 "가장 짧은 통과 응답"을 고른 규칙의 영향일 수 있다. 단어 수 상한(3 → 11)의 개선 일부는 길이가 줄어든 효과와 구분하지 못했다.
- **작은 규모다.** 0.5B 모델, 단일 시드, 시험 160문항, 학습 예시 115개다. 공개 벤치마크(IFEval) 점수가 아니고, 다른 모델·규모에서 같은 효과를 확인하지 않았다.
- **회귀 확인이 좁다.** 일반 능력은 두 자리 수 덧셈·뺄셈 60문항과 제약 없는 40문항의 형식만 봤다. 응답 내용의 정확성·유용성은 평가하지 않았다.
- **강화학습이 아니다.** 검사기 통과 응답을 다시 배우게 한 지도 미세조정이다. 정책 기울기(PPO·GRPO)는 쓰지 않았다.


## 재현

```bash
python -m venv .venv && .venv/Scripts/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/Scripts/pip install "transformers>=4.45,<5" "peft>=0.13" accelerate safetensors pytest
python -m pytest -q tests          # 검사기 시험
cd src && python build_data.py     # 문항 생성(커밋된 data/와 같아야 한다)
cd .. && PY=.venv/Scripts/python bash run_all.sh   # 거부 샘플링 → 학습 → 세 조건 생성 → 지표
```

이 노트북에서 걸린 시간: 거부 샘플링 약 2시간 13분(표본 1,440개), 학습 약 10분(627초), 조건마다 평가 생성 약 16~19분. 기본 모델은 허브 커밋 `7ae5576`에 고정했다(Apache-2.0). 기본 모델 가중치는 이 저장소에 없다.

## 만든 방식

설계·코드·실행은 AI 코딩 도구(Claude Code)와 함께 했다. 판정 함수는 시험으로 고정했고, 결과 수치는 `results/`의 파일에서 다시 계산할 수 있다.
