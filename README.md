# 작은 지시 모델의 형식 지시 위반을 자기 응답 거부 샘플링 LoRA로 줄일 수 있는가

[![tests](https://github.com/wpalswpa/rft-instruction-following/actions/workflows/tests.yml/badge.svg)](https://github.com/wpalswpa/rft-instruction-following/actions/workflows/tests.yml)

## 결과

| 처음 보는 시험 160문항, 모든 제약 통과 비율 | |
|---|---|
| 기본 모델 Qwen2.5-0.5B-Instruct (B0) | 14.4% (23/160) |
| 프롬프트 기준선: 시스템 문구 한 줄 추가 (B1) | **14.4% (23/160)** |
| 거부 샘플링 LoRA (M1), 학습 시드 3회 | **35.6% ± 6.0%p** (64 · 46 · 61) |
| 같은 표본에서 통과 응답을 무작위로 고른 LoRA, 시드 3회 | 32.3% ± 1.6%p (52 · 49 · 54) |

- 프롬프트 한 줄로는 오르지 않았고, 검사기를 통과한 자기 응답으로 학습하면 세 시드 모두 올랐다(첫 실험 시드 42에서 M1 − B1 +25.6%p, McNemar p = 8.2×10⁻¹⁰).
- **공짜는 아니었다.** 응답 단어 수 중앙값이 93에서 64~78로 줄었다. 다만 통과 응답을 무작위로 골라 응답이 더 긴 조건에서도 비슷하게 올라, 향상이 "가장 짧은 응답 고르기"에서만 나온 것은 아니다.
- 산술 대조 60문항은 47 → 46~48, 제약 없는 40문항에서 요청하지 않은 형식은 모든 실행에서 0이었다.
- 평가 기준·비교 조건·성공 기준은 학습 전에 [설계서](docs/blueprint.md)로 커밋했다(첫 실험 3bba7e1, 확장 실험 3fc898d).

## 질문

Qwen2.5-0.5B-Instruct가 "정확히 3개의 글머리표로", "쉼표를 쓰지 마라" 같은 형식 지시를 얼마나 어기는지 재고, 검사기를 통과한 자기 응답만으로 LoRA 미세조정(거부 샘플링 미세조정, RFT)을 해서 위반이 줄어드는지 본다. 같은 효과를 시스템 프롬프트로 얻을 수 있다면 학습은 필요 없다.

## 실험 설계

```
학습 문항 360개 (주제 60개 × 제약 1~2개, 시드 1234)
  → 기본 모델 응답 4개씩, 온도 0.8 (표본 1,440개)
  → 결정적 검사기로 모든 제약을 통과한 응답만 남김 (202개, 115문항)
  → 문항당 통과 응답 하나 선택: S 가장 짧은 것(첫 실험) · R 무작위(확장 실험)
  → LoRA (r 16, q·k·v·o, 응답 토큰에만 손실, 2에폭, 29단계)
  → 시험 160문항(처음 보는 주제 20개 + 처음 보는 제약 값), 탐욕 디코딩 256토큰
```

| 조건 | 모델 | 시스템 문구 |
|---|---|---|
| B0 | 기본 모델 | Qwen 기본 문구 |
| B1 | 기본 모델 | 기본 문구 + "Follow every formatting instruction in the user's message exactly." |
| M1 | LoRA 모델 | Qwen 기본 문구 |

판정은 [src/constraints.py](src/constraints.py)의 결정적 함수 8종이 하고, 함수마다 통과·실패 예시를 [tests/](tests/test_constraints.py)에 두었다. 학습·시험은 주제와 제약 값 둘 다로 나눠 겹치지 않게 했고, 문항 생성 스크립트가 겹침을 단언한다. 문항 재현은 CI가 확인한다.

## 실패 분석: 어떤 지시가 오르고 어떤 지시가 안 올랐나

| 제약 | B0 | B1 | S 시드 42 · 43 · 44 | R 시드 42 · 43 · 44 | 학습 예시 |
|---|---:|---:|---:|---:|---:|
| json_keys (키를 정한 JSON) | 0/12 | 0/12 | 12 · 12 · 12 | 12 · 12 · 12 | 20 |
| bullets (정확히 n개) | 5/25 | 4/25 | 20 · 14 · 17 | 13 · 16 · 16 | 32 |
| quote_wrap (큰따옴표로 감싸기) | 16/30 | 15/30 | 27 · 23 · 20 | 21 · 21 · 26 | 19 |
| lowercase (전부 소문자) | 14/38 | 14/38 | 26 · 13 · 22 | 25 · 19 · 19 | 19 |
| max_words (n단어 이하) | 3/31 | 2/31 | 11 · 10 · 10 | 9 · 11 · 8 | 5 |
| end_phrase (정한 문구로 끝내기) | 8/25 | 11/25 | 10 · 7 · 15 | 9 · 9 · 10 | 7 |
| no_commas (쉼표 금지) | 1/35 | 1/35 | 6 · 3 · 6 | 3 · 1 · 2 | 4 |
| keyword_twice (단어 두 번 이상) | 2/26 | 1/26 | 1 · 3 · 3 | 3 · 2 · 3 | 21 |

- **가장 크게 오른 것은 출력 껍데기를 바꾸는 지시다.** 기본 모델은 JSON을 코드 블록(```)으로 감싸 0/12였는데, 여섯 실행 모두 학습에 없던 키 이름으로 12/12가 됐다.
- **학습 신호가 적은 지시는 그대로였다.** 쉼표 금지(학습 예시 4개)와 끝 문구(7개)는 거의 오르지 않았다. 기본 모델의 표본 통과율이 3%·15%라 거부 샘플링으로 모을 예시가 적었다.
- **예시가 많아도 안 오른 지시가 있다.** "단어를 두 번 이상"은 학습 예시가 21개였지만 여섯 실행 모두 1~3/26이었다. 내용 생성 중에 단어 빈도를 세야 하는 지시라, 형식을 흉내 내는 것만으로는 배워지지 않는 것으로 보인다(가설).
- **단어 수 상한은 길이 지름길이 아니었다.** 가장 짧은 응답을 고른 S(평균 10.3/31)와 무작위로 고른 R(9.3/31)이 비슷했다. 다만 둘 다 B0보다 응답이 짧아져, 길이 감소 자체의 기여는 남는다.

## 다음 실험

1. 쉼표 금지·끝 문구처럼 표본 통과율이 낮은 제약은 문항당 표본을 늘리거나(k 4 → 16) 제약별로 학습 예시 수를 맞춘다.
2. "단어 두 번 이상"이 왜 안 오르는지 응답을 분류한다(단어를 한 번만 씀 / 형태 변화 / 아예 안 씀).
3. 공개 평가 IFEval 541문항으로 같은 방향이 유지되는지 확인한다(설계 10.2절, 실행 중).

## 재현

```bash
python -m venv .venv && .venv/Scripts/pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
.venv/Scripts/pip install -r requirements.txt
python -m pytest -q tests                           # 검사기 시험
cd src && python build_data.py && cd ..             # 문항 생성(커밋된 data/와 같아야 한다)
PY=.venv/Scripts/python bash run_all.sh            # 첫 실험: 거부 샘플링 → 학습 → B0·B1·M1 생성 → 지표
PY=.venv/Scripts/python bash run_ext.sh            # 확장 실험: 시드·선택 규칙 5회 학습·평가 → IFEval
```

기본 모델은 허브 커밋 `7ae5576`에 고정했다(Apache-2.0, 가중치는 저장소에 없음). 노트북 CPU(i7-8750H, 16GB)에서 거부 샘플링 약 2시간 13분, 학습 약 10분, 조건마다 평가 약 16~19분이 걸렸다. 첫 실험의 어댑터는 `adapter/`(8.3MB)에 있다.

## 한계

- 0.5B 모델 하나, 학습 시드 3개, 자체 시험 160문항, 학습 예시 115개다. 다른 모델·규모에서 같은 효과를 확인하지 않았다.
- 응답 내용의 정확성·유용성은 평가하지 않았다. 일반 능력은 두 자리 수 덧셈·뺄셈 60문항과 제약 없는 40문항의 형식만 봤다.
- 강화학습이 아니다. 검사기 통과 응답을 다시 배우게 한 지도 미세조정이다(정책 기울기 없음).
- 시드 간 차이(46~64)가 조건 간 차이(S와 R)보다 크다. S와 R의 차이(3.3%p)를 선택 규칙의 효과로 읽지 않는다.

## 만든 방식

설계·코드·실행은 AI 코딩 도구(Claude Code)와 함께 했다. 성공 기준과 비교 조건은 결과를 보기 전에 커밋했고, 모든 수치는 `results/`의 생성 결과에서 다시 계산할 수 있다.
