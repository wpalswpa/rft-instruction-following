# 설계서: 검증 가능한 지시 따르기를 거부 샘플링 미세조정으로 올릴 수 있는가

작성 2026-10-05. 이 문서는 학습과 평가를 돌리기 전에 커밋한다. 결과를 본 뒤 성공 기준·비교 조건·평가 데이터를 바꾸지 않는다. 바꿔야 하면 바꾼 이유를 "변경 기록"에 남긴다.

## 1. 목적과 범위

- **질문.** 작은 지시 모델(Qwen2.5-0.5B-Instruct)이 형식 지시("정확히 3개의 글머리표", "쉼표 금지" 등)를 어기는 비율을, 검사기를 통과한 자기 생성 응답만으로 LoRA 미세조정(거부 샘플링 미세조정, RFT)해 줄일 수 있는가. 같은 효과를 프롬프트만으로 얻을 수 있다면 학습은 필요 없다.
- **왜 이 과제인가.** 형식 지시는 정답 판정을 코드로 할 수 있어(검증 가능한 보상) 사람 평가 없이 재현 가능하게 잴 수 있다. 처음 해 보는 post-training을 작은 규모로, 평가를 먼저 고정한 채 해 보는 것이 목적이다.
- **하지 않는 것.** 최고 성능 경쟁, 대형 모델, 강화학습(PPO·GRPO), 사람 선호 데이터, 한국어 지시, 공개 벤치마크(IFEval) 점수 주장. 이 실험의 수치는 이 저장소가 만든 검사 문항에서만 유효하다.
- **환경.** GPU 없음(i7-8750H CPU, 메모리 16GB). 그래서 0.5B 모델, LoRA, 짧은 응답으로 규모를 정했다.

## 2. 검사 가능한 제약 8종

모든 판정은 `src/constraints.py`의 결정적 함수가 한다. 공백 앞뒤 제거 뒤 판정한다.

| 이름 | 지시 | 통과 조건 |
|---|---|---|
| json_keys | 코드 블록 없이 키 {a, b}만 가진 JSON 객체로만 답하라 | 응답 전체가 JSON 객체이고 키 집합이 정확히 일치 |
| bullets | 정확히 n개의 "- " 글머리표로만 답하라 | 빈 줄을 뺀 모든 줄이 "- "로 시작하고 개수가 n |
| lowercase | 응답 전체를 소문자로 | 영문자가 있고 `text == text.lower()` |
| max_words | n단어 이하로 | 공백 기준 단어 수 ≤ n |
| keyword_twice | 단어 w를 두 번 이상 | 대소문자 무시, 단어 경계 기준 등장 ≥ 2 |
| end_phrase | 정확히 문구 p로 끝내라 | 끝 공백 제거 뒤 p로 끝남 |
| no_commas | 쉼표를 쓰지 마라 | "," 없음 |
| quote_wrap | 응답 전체를 큰따옴표로 감싸라 | 큰따옴표로 시작하고 끝나며 길이 ≥ 2 |

한 문항에는 제약을 1~2개 붙인다. 서로 모순되는 조합(json_keys와 bullets·end_phrase·quote_wrap·lowercase, bullets와 quote_wrap 등)은 만들지 않는다. 조합 규칙은 코드의 `INCOMPATIBLE`에 있다.

## 3. 데이터와 분할(누수 방지)

- **주제.** 영어 일반 주제 80개를 고정 순서로 두고 앞 60개는 학습, 뒤 20개는 시험에만 쓴다.
- **제약 값.** 글머리표 수·단어 상한·키워드·끝 문구·JSON 키 이름은 학습용과 시험용 목록을 따로 둔다(겹치지 않음). 시험은 "처음 보는 주제 + 처음 보는 값"이다.
- **문항 수.** 학습 360문항(주제 60 × 6), 시험 160문항(주제 20 × 8), 제약 없는 대조 문항 40개(시험 주제), 산술 대조 문항 60개.
- **검사.** 생성 스크립트가 주제·값·문항 문자열이 분할 사이에 겹치지 않는지 단언하고, 겹치면 멈춘다. 난수 시드 1234.

## 4. 방법

1. **학습 데이터 만들기(거부 샘플링).** 학습 문항마다 기본 모델로 응답 4개를 온도 0.8(top-p 1.0, top-k 끔, 시드 2026)로 뽑고, 모든 제약을 통과한 응답만 남긴다. 문항당 통과 응답이 여러 개면 가장 짧은 것 하나를 고른다(길이 편향을 줄이려고 미리 정한 규칙). 통과 응답이 없는 문항은 버린다. 다른 모델(교사)은 쓰지 않는다.
2. **미세조정.** LoRA(r 16, alpha 32, dropout 0.05, 대상 q·k·v·o 투영), AdamW 학습률 2e-4(앞 5% 선형 워밍업 뒤 0까지 선형 감소), 2에폭, 배치 1 × 기울기 누적 8, 최대 길이 512토큰, 시드 42. 손실은 응답 토큰에만 건다(프롬프트 토큰은 -100). 하이퍼파라미터는 이 값으로 고정하고 시험 결과를 보고 고치지 않는다(검증용 분할이 없으므로 튜닝하지 않는다).
3. **평가.** 시험 160문항을 탐욕 디코딩(최대 256토큰)으로 세 조건에서 생성한다.
   - B0 기본 모델, 지시만.
   - B1 기본 모델 + 시스템 지시 "Follow every formatting instruction in the user's message exactly."(프롬프트만으로 얻을 수 있는 개선). 세 조건과 학습 데이터 모두 Qwen2.5 템플릿의 기본 시스템 문구를 쓰고, B1만 그 뒤에 이 문장을 덧붙인다.
   - M1 미세조정 모델, 지시만.

## 5. 지표와 성공 기준(학습 전 고정)

- **주 지표.** 문항 단위 엄격 통과율(문항의 모든 제약 통과).
- **보조 지표.** 제약 단위 통과율, 제약 종류별 통과율, 응답 단어 수.
- **통계.** M1과 B1의 문항 단위 쌍 비교에 McNemar 정확 검정(양측), 차이의 95% 부트스트랩 구간(10,000회, 시드 7).
- **성공 기준.** (1) 주 지표에서 M1 − B1 ≥ +10%p이고 McNemar p < 0.05. (2) 산술 대조 정확도 하락이 5%p 이하. (3) 제약 없는 대조 문항에서 요청하지 않은 형식(전부 소문자·큰따옴표 감싸기·끝 문구·글머리표만)을 쓴 비율이 10% 이하.
- **판정.** 셋 다 만족하면 "이 조건에서 효과 있음", (1)만 실패하면 "프롬프트 대비 이점 확인 못 함", (2)나 (3)이 실패하면 "부작용 있음"으로 적는다. 어느 경우든 결과를 그대로 공개한다.

## 6. 위험과 대응

- **기본 통과율이 너무 낮으면** 거부 샘플링으로 남는 데이터가 적다. 학습 데이터가 100개 미만이면 문항당 샘플을 8개로 늘린다(이 규칙도 미리 정한다).
- **응답 길이 축소로 통과하는 지름길.** 짧은 응답이 max_words·no_commas를 쉽게 통과한다. 단어 수를 함께 보고, 짧아졌다면 그 사실을 적는다.
- **검사기 결함.** 판정 함수마다 통과·실패 예시를 `tests/`에 둔다.

## 7. 산출물과 완료 기준

- `src/` 코드, `tests/` 검사기 시험, `data/` 문항(생성 스크립트로 재현), `results/` 지표 JSON·조건별 생성 결과, README(결과·한계·재현 명령).
- 완료 기준: 위 검사기 시험 통과, 세 조건 평가 완료, 성공 기준 판정과 한계가 README에 적힘, 모델 가중치는 저장소에 올리지 않음(LoRA 어댑터는 크기를 보고 결정).

## 8. 이해해야 할 설계 판단(면접 대비)

- 왜 RFT인가: 보상을 코드로 판정할 수 있어 강화학습 없이도 "통과한 행동만 다시 배우게" 할 수 있다. RLVR의 가장 단순한 형태로 볼 수 있지만 같은 것은 아니다(정책 기울기 없음).
- 왜 B1을 두는가: 학습 없이 프롬프트로 같은 효과가 나면 학습 비용을 쓸 이유가 없다.
- 왜 응답 토큰에만 손실을 거는가: 프롬프트까지 배우면 지시문을 따라 쓰는 쪽으로 기울고, 응답 품질 신호가 희석된다.
- 왜 분할을 주제·값 둘 다로 나누는가: 같은 주제나 같은 키워드를 외워 통과하는 경우를 시험에서 빼려고.

## 9. 변경 기록

- 2026-10-05 11:35, 결과를 보기 전. CPU에서 첫 실행을 재 보니 묶음 64개가 11분(생성 1건당 약 10초)이라 학습 데이터 생성에만 4시간이 넘었다. 실행을 멈추고 묶음을 32개로(앞선 측정에서 1건당 6.3초), 거부 샘플링 표본의 최대 길이를 192토큰으로 줄였다. 평가 생성은 256토큰 그대로다. 표본 수(문항당 4개)·온도·성공 기준·평가 조건은 바꾸지 않았다. 첫 실행의 표본은 쓰지 않는다.

- 2026-10-05 15:00, 결과를 본 뒤. `metrics.json`의 McNemar p값이 소수 6자리 반올림으로 0.0이 되어 유효숫자 3자리 표기로 바꿨다(계산식은 그대로). 학습된 어댑터(8.3MB)를 `adapter/`에 넣고, 평가 스크립트가 `outputs/lora`가 없으면 그것을 쓰게 했다. 판정 기준·데이터·생성 결과는 바꾸지 않았다.
